# アプリを配置する前の環境を構築する

## Mission

**Terraform で、Todo アプリを配置する手前までの環境を構築します。** 仮想ネットワーク・仮想マシン・Azure SQL Database ができた状態から、アプリの配置を演習できます。

**アプリは入りません。** VM には nginx だけが導入され、既定のページが表示されます。**SQL のファイアウォール規則も作りません。** どちらも演習で扱う対象のためです。

**自動化される範囲は、手作業の手順と見比べると分かります。** 対応は次のとおりです（[Todo アプリの構築手順](../../../docs/build-todo-app.md)の番号に対応します）。

| 作られるもの                           | 手作業での手順 |
| -------------------------------------- | -------------- |
| 仮想ネットワーク・サブネット・受信規則 | 手順 3・4      |
| Azure SQL Database（無料オファー）     | 手順 2         |
| SSH 鍵と VM                            | 手順 3・5-1    |
| 接続情報（`.env`）の作成               | 手順 5-2       |
| SSH の接続コマンドの出力               | 手順 6         |

**手順 5-3 以降は受講者が手で行います。** 内容は「[このあとの手順](#このあとの手順)」にまとめています。

**手作業の手順はコース内ラボ環境向けではありません。** ご自身のサブスクリプションで実施する内容のため、コース内ラボでは手順 5-3 以降だけを実施してください。

## 注意事項

> [!CAUTION]
> このラボは Udemy のコース内ラボ環境（ワークスペース）での実施を前提としています。
> ご自身の Azure サブスクリプションなどコース外の環境で実施すると、リソースの利用料金が発生します。
> コース外の環境で発生した課金について、講師は一切の責任を負いかねますのであらかじめご了承ください。

**このアプリにはログイン認証がありません。** URL に到達した人は誰でもタスクを追加・削除できます。動作確認用のタスク以外を入力しないでください。

## 事前準備

1. Azure Cloud Shell（Bash）を起動します。**ストレージの確認を求められたら「ストレージ アカウントは必要ありません」を選びます**（エフェメラル）
2. **ご自身のサブスクリプションで実行する場合のみ**、使用するリソースグループ名を宣言します

   ```bash
   export TF_VAR_resource_group_name="rg-iaas"
   ```

   **コース内ラボ環境では不要です。** 用意されたリソースグループを自動で検出します。

   **自動検出したリソースグループに既存のリソースがある場合は、続けてよいか確認を求めます。** 片付けはリソースグループごとの削除のため、既存のリソースも消えるためです。

3. 次のコマンドを実行します（5〜10 分かかります）

   ```bash
   curl -fsSL https://raw.githubusercontent.com/m-oka-system/mssql-todo-app/refs/heads/main/labs/sections/section07/setup.sh | bash
   ```

4. `Apply complete!` と表示されたら作成完了です

**リソースグループは作りません。** 既にあるものの中へリソースを作ります。

**スクリプトと Terraform は、初回にリポジトリの最新版（`main`）を取得します。** 版を固定していないため、教材を改訂すると動画の収録時と異なる場合があります。**Azure プロバイダのバージョンだけは固定しています。**

**2 回目以降は取得し直しません。** 取得済みのものをそのまま使い、`terraform apply` を実行します。差分がなければ `No changes.` と表示されて終わります。**最新版で試したい場合は、`~/mssql-todo-app` を削除してから実行してください。**

## Challenge

### 作られたものを確認する

Azure ポータルでリソースグループを開き、次が作られていることを確認します。

| リソース                         | 名前                  |
| -------------------------------- | --------------------- |
| 仮想ネットワーク                 | `vnet`                |
| サブネット                       | `snet-vm`             |
| ネットワークセキュリティグループ | `nsg-vm`              |
| 仮想マシン                       | `vm01`                |
| SQL サーバー                     | `sql-iaas-<ランダム>` |
| SQL データベース                 | `todo`                |

### VM が応答することを確認する

`terraform apply` を実行したディレクトリで、出力を確認します。

```bash
cd ~/mssql-todo-app/labs/sections/section07
terraform output -raw app_url
```

**`-raw` を付けないと引用符が付いて、そのままでは開けません。**

表示された URL をブラウザで開くと、**nginx の既定のページが表示されます。** アプリはまだ入っていないため、この時点ではこれが正常です。

### VM へ接続する

```bash
terraform output -raw ssh_command
```

出力されたコマンドをそのまま貼り付けて実行します。**秘密鍵は `~/.ssh/ssh-key-<ランダムな 5 文字>.pem` に保存されています。**

### このあとの手順

**ここからは[構築手順](../../../docs/build-todo-app.md)の手順 5-3 以降を手で進めます。**

| 手順     | 実行場所    | 内容                                                       |
| -------- | ----------- | ---------------------------------------------------------- |
| 手順 5-3 | Cloud Shell | `.env` を VM のホームへ送る                                |
| 手順 6   | Cloud Shell | SSH で VM へ接続する                                       |
| 手順 7   | VM          | VM の送信元 IP を SQL サーバーのファイアウォールへ登録する |
| 手順 8   | VM          | アプリを取得する                                           |
| 手順 9   | VM          | セットアップスクリプトを `--env-file` 付きで実行する       |
| 手順 10  | ブラウザ    | 動作を確認する                                             |

**Cloud Shell と VM を行き来するのは 1 回だけです。** 手順 6 で接続したら、あとは VM 上で終わります。

**手順 5-2（`.env` の作成）は不要です。** `terraform apply` が Cloud Shell の `~/mssql-todo-app/src/.env` へ書き出しています。手順 5-3 は次のコマンドに置き換えてください。

```bash
cd ~/mssql-todo-app/labs/sections/section07
$(terraform output -raw scp_env_command)
```

**鍵の名前と VM の IP はラボごとに変わります。** 出力にそのまま実行できる形で入っているため、組み立てる必要はありません。

**配置は手順 9 のスクリプトが行います。** `sudo deploy/setup.sh --env-file ~/.env` を実行すると、`/opt/todo/src/.env` への配置まで終わります。所有者やパーミッションを指定する必要はなく、サービスの再起動も要りません。

**手順 7 を飛ばすと、接続情報が正しくてもデータベースに到達できません。** 画面には「データベースに接続できません」とだけ表示されます。

## 確認

次の 3 つが確認できれば、ラボが用意する範囲は完了です。

| 確認すること           | 方法                                          |
| ---------------------- | --------------------------------------------- |
| VM が応答すること      | `app_url` を開くと nginx の既定のページが出る |
| VM へ接続できること    | `ssh_command` でログインできる                |
| データベースがあること | ポータルに `todo` データベースが表示される    |

**手順 5-3〜10 を終えると、同じ URL で Todo アプリの一覧が表示されます。**

**初回の表示に 1 分ほどかかる場合があります。** 異常ではありません。Azure SQL Database が自動一時停止から復帰するためです。

## 片付け

**確認が終わったら、Azure ポータルでリソースグループごと削除してください。**

**`terraform destroy` は使いません。** Terraform はリソースグループ自体を管理しておらず、作成したものはすべてその中にあります。**リソースグループを消せば確実に片付きます。**

**環境を残すとデータベースの無料枠を消費し続けます。** 外部からのアクセスが届き続けると自動一時停止が働かず、**約 1.7 日**で使い切ります。使い切ると翌月までそのデータベースを使えません。

### Cloud Shell に残るファイル

`terraform apply` は次の 3 つを、実行した端末に作ります。

| ファイル                        | 内容                     |
| ------------------------------- | ------------------------ |
| `src/.env`                      | **DB のパスワード**      |
| `~/.ssh/ssh-key-<ランダム>.pem` | **VM の秘密鍵**          |
| `terraform.tfstate`             | リソースの状態と接続情報 |

**エフェメラル（ストレージなし）で起動した場合は、セッションが切れるとまとめて消えます。** 事前準備の手順 1 で選んでいれば、操作は不要です。

**ストレージをマウントしている場合は残り続けます。** 次を実行して消してください。

```bash
rm -rf ~/mssql-todo-app ~/.ssh/ssh-key-*.pem
```

## 補足

**`terraform apply` を実行した端末の IP は、SSH の受信規則へ自動で許可されます。** 別の端末からも接続する場合は、`setup.sh` ではなく手で実行し、変数を追加します。

```bash
cd ~/mssql-todo-app/labs/sections/section07
export TF_VAR_resource_group_name="<リソースグループ名>"
terraform apply -var='allowed_client_ip=["<IP>"]'
```

**`TF_VAR_resource_group_name` の宣言が要ります。** `setup.sh` が設定した値はスクリプトのプロセス内だけのもので、Cloud Shell には残りません。省くと入力待ちで止まります。

**SQL サーバーのファイアウォールには何も登録されません。** `allowed_client_ip` は SSH の受信規則だけに効きます。ポータルのクエリエディターを使う場合も、手順 7 と同じ画面で自分の IP を追加してください。

**アプリまで自動で構築するラボは[セクション 09](../section09/README.md) にあります。** 手作業と自動化を見比べる場合に使ってください。
