# Todo アプリの環境を Terraform で構築する

## Mission

**Terraform で、Todo アプリが動く環境をまとめて構築します。** 仮想ネットワーク・仮想マシン・Azure SQL Database の作成から、アプリの配置と起動までが 1 コマンドで終わります。

**何が自動化されるかは、手作業の手順と見比べると分かります。** 対応は次のとおりです（[Todo アプリの構築手順](../../../docs/build-todo-app.md)の番号に対応します）。

| 作られるもの                               | 手作業での手順 |
| ------------------------------------------ | -------------- |
| 仮想ネットワーク・サブネット・受信規則     | 手順 3・4      |
| Azure SQL Database（無料オファー）         | 手順 2         |
| SSH 鍵と VM                                | 手順 3・5-1    |
| SSH の接続コマンドの出力                   | 手順 6         |
| SQL のファイアウォール規則                 | 手順 7         |
| アプリの取得・セットアップ・接続情報・起動 | 手順 5-2・8・9 |

**手作業の手順はコース内ラボ環境向けではありません。** ご自身のサブスクリプションで実施する内容のため、コース内ラボでは読むだけにしてください。

## 注意事項

> [!CAUTION]
> このラボは Udemy のコース内ラボ環境（ワークスペース）での実施を前提としています。
> ご自身の Azure サブスクリプションなどコース外の環境で実施すると、リソースの利用料金が発生します。
> コース外の環境で発生した課金について、講師は一切の責任を負いかねますのであらかじめご了承ください。

**このアプリにはログイン認証がありません。** URL に到達した人は誰でもタスクを追加・削除できます。動作確認用のタスク以外を入力しないでください。

## 事前準備

1. Azure Cloud Shell（Bash）を起動します。**ストレージの確認を求められたら「ストレージ アカウントは必要ありません」を選びます**（エフェメラル）
2. **ご自身のサブスクリプションで実行する場合のみ**、使用するリソースグループ名を宣言します

   ```bash
   export TF_VAR_resource_group_name="rg-iaas"
   ```

   **コース内ラボ環境では不要です。** 用意されたリソースグループを自動で検出します。

   **リソースグループが空でない場合は中止します。** 片付けはリソースグループごとの削除のため、他のリソースと同居させません。

   **2 回目以降はそのまま進みます。** 前回の記録（`terraform.tfstate`）があれば、同じ構成を当て直すだけになるためです。差分がなければ `No changes.` で終わります。

3. 次のコマンドを実行します（5〜10 分かかります）

   ```bash
   curl -fsSL https://raw.githubusercontent.com/m-oka-system/mssql-todo-app/refs/heads/main/labs/sections/section09/setup.sh | bash
   ```

4. `Apply complete!` と表示されたら作成完了です

**リソースグループは作りません。** 既にあるものの中へリソースを作ります。

**スクリプトと Terraform は、初回にリポジトリの最新版（`main`）を取得します。** 版を固定していないため、教材を改訂すると動画の収録時と異なる場合があります。**Azure プロバイダのバージョンだけは固定しています。**

**2 回目以降は取得し直しません。** 取得済みのものをそのまま使い、`terraform apply` を実行します。差分がなければ `No changes.` と表示されて終わります。**最新版で試したい場合は、`~/mssql-todo-app` を削除してから実行してください。**

## Challenge

### 作られたものを確認する

Azure ポータルでリソースグループを開き、次が作られていることを確認します。

| リソース                         | 名前                  |
| -------------------------------- | --------------------- |
| 仮想ネットワーク                 | `vnet`                |
| サブネット                       | `snet-vm`             |
| ネットワークセキュリティグループ | `nsg-vm`              |
| 仮想マシン                       | `vm01`                |
| SQL サーバー                     | `sql-iaas-<ランダム>` |
| SQL データベース                 | `todo`                |

### アプリを開く

`terraform apply` を実行したディレクトリで、出力を確認します。

```bash
cd ~/mssql-todo-app/labs/sections/section09
terraform output -raw app_url
```

**`-raw` を付けないと引用符が付いて、そのままでは開けません。**

表示された URL をブラウザで開き、タスクの追加・完了状態の変更・削除を試します。

### VM へ接続する

```bash
terraform output -raw ssh_command
```

出力されたコマンドをそのまま貼り付けて実行します。**秘密鍵は `~/.ssh/ssh-key-<ランダムな 5 文字>.pem` に保存されています。**

## 確認

次の 3 つが確認できれば完了です。

| 確認すること                     | 方法                                         |
| -------------------------------- | -------------------------------------------- |
| アプリが応答すること             | ブラウザで一覧が表示され、タスクを追加できる |
| どの VM が応答したか分かること   | 画面の下端にホスト名とプライベート IP が出る |
| 接続先のデータベースが正しいこと | 画面の下端の DB 名が `todo` になっている     |

**同じ情報は `curl <app_url>/healthz` でも取得できます。**

**初回の表示に 1 分ほどかかる場合があります。** 異常ではありません。Azure SQL Database が自動一時停止から復帰するためです。

## 片付け

**確認が終わったら、Azure ポータルでリソースグループごと削除してください。**

**`terraform destroy` は使いません。** Terraform はリソースグループ自体を管理しておらず、作成したものはすべてその中にあります。**リソースグループを消せば確実に片付きます。**

**環境を残すとデータベースの無料枠を消費し続けます。** 外部からのアクセスが届き続けると自動一時停止が働かず、**約 1.7 日**で使い切ります。使い切ると翌月までそのデータベースを使えません。

### Cloud Shell に残るファイル

`terraform apply` は次の 3 つを、実行した端末に作ります。

| ファイル                        | 内容                     |
| ------------------------------- | ------------------------ |
| `src/.env`                      | **DB のパスワード**      |
| `~/.ssh/ssh-key-<ランダム>.pem` | **VM の秘密鍵**          |
| `terraform.tfstate`             | リソースの状態と接続情報 |

**エフェメラル（ストレージなし）で起動した場合は、セッションが切れるとまとめて消えます。** 事前準備の手順 1 で選んでいれば、操作は不要です。

**ストレージをマウントしている場合は残り続けます。** 次を実行して消してください。

```bash
rm -rf ~/mssql-todo-app ~/.ssh/ssh-key-*.pem
```

## 補足

**`terraform apply` を実行した端末の IP は自動で許可されます。** 別の端末からも接続する場合は、`setup.sh` ではなく手で実行し、変数を追加します。

```bash
cd ~/mssql-todo-app/labs/sections/section09
export TF_VAR_resource_group_name="<リソースグループ名>"
terraform apply -var='allowed_client_ip=["<IP>"]'
```

**`TF_VAR_resource_group_name` の宣言が要ります。** `setup.sh` が設定した値はスクリプトのプロセス内だけのもので、Cloud Shell には残りません。省くと入力待ちで止まります。

**`terraform apply` が完了した時点で、アプリは応答します。** 拡張機能の完了まで Terraform が待つためです。

**アプリを更新したいときは、リソースグループごと削除して作り直してください。** VM 上には作業用のリポジトリが残りません（取得したものを一時ディレクトリへ置いて削除します）。
